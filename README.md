# Congress.gov API MCP Server

This is a Model Context Protocol (MCP) server designed to provide access to the official Congress.gov API (v3) using a hybrid approach:

* **MCP Resources:** For direct lookups of core legislative entities (Bills, Members, Congresses, Committees, general Info) using standardized URIs.
* **MCP Tools:** For more complex operations like searching across collections (`congress_search`) and retrieving related data lists (`congress_getSubResource`).

This server acts as a bridge, allowing MCP clients (like AI assistants or development tools) to easily query and utilize U.S. legislative data.

## Project Structure

* `/src`: Contains all source code.
  * `/config`: Configuration management (`ConfigurationManager.ts`).
  * `/services`: Core logic for interacting with Congress.gov API (`CongressApiService.ts`, `RateLimitService.ts`).
  * `/tools`: MCP tool definitions (`search/`, `subresource/`, `index.ts`).
  * `/types`: TypeScript interfaces and Zod schemas.
  * `/utils`: Shared utility functions (logging, errors, etc.).
  * `resourceHandlers.ts`: Logic for handling core entity resource requests.
  * `createServer.ts`: Server instance creation, resource and tool registration.
  * `server.ts`: Main application entry point.
* `/dist`: Compiled JavaScript output (generated by `npm run build`).
* `/docs`: Project documentation (PRD, Feature Spec, RFCs).
* `package.json`: Project metadata and dependencies.
* `tsconfig.json`: TypeScript compiler options.
* `.eslintrc.json`, `.prettierrc.json`: Linting and formatting rules.
* `.env`: (Not committed) For storing `CONGRESS_GOV_API_KEY`.

## Getting Started

1. **Install Dependencies:**

    ```bash
    npm install
    ```

2. **Set API Key:** Create a `.env` file in the project root and add your Congress.gov API key:

    ```
    CONGRESS_GOV_API_KEY=YOUR_API_KEY_HERE
    ```

    (Get a key from [https://api.data.gov/signup/](https://api.data.gov/signup/))
3. **Build the Server:**

    ```bash
    npm run build
    ```

4. **Run the Server:**

    ```bash
    npm start
    ```

    (This runs `node dist/server.js`)

The server typically starts on port `8080` (configurable via environment variable `CONGRESS_MCP_SERVER_PORT`, if implemented - check `src/server.ts`).

Alternatively, run in development mode using `npm run dev` (uses `ts-node` and `nodemon`).

## Querying the Server (MCP Interaction)

This server adheres to the Model Context Protocol (MCP). Interactions occur by sending JSON requests to the server's `/mcp` endpoint via HTTP POST.

### General Request Structure

All tool calls should use the `callTool` request type:

```json
{
  "type": "callTool",
  "id": "your-unique-request-id", // Client-generated unique ID for the request
  "tool": "tool_name_here",       // e.g., "congress_search" or "congress_getSubResource"
  "parameters": {
    // Tool-specific parameters as a JSON object
    // See tool descriptions below or use MCP describeTool for details
  },
  "context": {
    "sessionId": "your-session-id" // A unique ID for the conversation or session
  }
}
```
*   **`id`**: A unique identifier for each request, generated by the client.
*   **`tool`**: The name of the tool to execute (e.g., `congress_search`).
*   **`parameters`**: A JSON object containing the arguments for the tool. The specific structure varies per tool.
*   **`context.sessionId`**: A session identifier. It's recommended to provide a consistent `sessionId` for a given user interaction or conversation flow to help with logging, context tracking, and potentially future features like rate limiting per session.

### General Response Structure

A successful tool call will result in a `callToolResponse` JSON object:

```json
{
  "type": "callToolResponse",
  "id": "your-unique-request-id", // Matches the request ID
  "tool": "tool_name_here",
  "result": {
    "content": [
      {
        "type": "json", // For these tools, the content type is 'json'
        "json": {
          // The actual JSON data from the Congress.gov API
          // (e.g., search results, sub-resource details)
        }
      }
      // Potentially other content parts if the tool were to return multiple types
    ]
  }
}
```
*   The `result.content[0].json` field will contain the direct JSON response from the Congress.gov API for the requested operation.

If an error occurs (e.g., invalid parameters, API issues), the server will respond with an `mcpError` JSON object:
```json
{
  "type": "mcpError",
  "id": "your-unique-request-id", // Matches the request ID
  "tool": "tool_name_here", // If applicable
  "error": {
    "code": "ErrorCodeName", // e.g., "InvalidParams", "InternalError"
    "message": "A human-readable error message.",
    "details": { /* Optional additional details */ }
  }
}
```

### Using Tools (`callTool`)

To use the tools provided by this server (`congress_search`, `congress_getSubResource`), construct a `callTool` JSON request as described in "General Request Structure" and POST it to the `/mcp` endpoint.

The following examples use a conceptual XML-like syntax that some MCP clients might use. **Remember that the actual communication with this server is JSON.** The `arguments` block in these examples maps to the `parameters` object in the JSON `callTool` request.

**!!! CRITICAL TOOL WORKFLOW: Finding Entities & Getting Related Data !!!**

Many common tasks require a **mandatory two-step process** using both tools:

1. **STEP 1: Find the Entity ID using `congress_search`**
    * **Purpose:** Locate the specific bill, member, committee, etc., you need and extract its unique identifier(s) (e.g., `memberId`, or the `congress`, `billType`, `billNumber` for a bill URI).
    * **Tool:** `congress_search`
    * **Example (JSON `parameters` for `congress_search`):** Find member "John Kennedy":
        ```json
        {
          "collection": "member",
          "query": "John Kennedy"
        }
        ```
    * **Output:** The response `result.content[0].json` will contain the search results. Look for the `memberId` (e.g., `K000393`) or other necessary identifiers in this JSON data.
    * **!!! WARNING !!!** Searching might return multiple results. You **MUST** identify the correct entity and use its specific ID for the next step.
    * **!!! API LIMITATION !!!** Filtering general searches by `congress` using the `filters` parameter is **NOT SUPPORTED** by the underlying API (e.g., for `/v3/bill` or `/v3/member`) and will be ignored. Congress-specific filtering usually requires using specific API paths (e.g., `/v3/bill/117`), which the `congress_search` tool does not construct directly.

2. **STEP 2: Get Related Data using `congress_getSubResource`**
    * **Purpose:** Use the identifier(s) found in Step 1 to construct the `parentUri` and fetch related details (actions, sponsors, text, etc.).
    * **Tool:** `congress_getSubResource`
    * **Prerequisite:** You **MUST** have the correct `parentUri` (e.g., `congress-gov://member/K000393`) from Step 1.
    * **Example (JSON `parameters` for `congress_getSubResource`):** Get legislation sponsored by member `K000393`:
        ```json
        {
          "parentUri": "congress-gov://member/K000393",
          "subResource": "sponsored-legislation",
          "limit": 5
        }
        ```
    * **!!! GUARANTEED ERROR WARNING !!!** You **MUST** use a `subResource` string that is **STRICTLY VALID** for the `parentUri` type (e.g., `'sponsored-legislation'` for members, `'actions'` for bills). Providing an invalid combination **WILL** cause an error. The detailed descriptions for the `subResource` parameter (available via MCP `describeTool` or by inspecting `src/tools/subresource/getSubResourceParams.ts`) list valid combinations.

**Following this two-step process is ESSENTIAL for reliably getting related information.**

### Tool Parameter Details

The specific parameters accepted by each tool are defined by Zod schemas within the server and are accompanied by detailed descriptions intended for LLM consumption. Clients can typically discover these details using the MCP `describeTool` functionality (if implemented by the client and server framework).

**`congress_search` Tool Parameters:**
*   `collection` (required, string enum): e.g., "bill", "member", "committee".
*   `query` (optional, string): Keywords for searching.
*   `filters` (optional, object):
    *   `type` (optional, string): e.g., "hr", "s" for bills.
    *   `fromDateTime` (optional, string ISO8601): e.g., "2023-01-01T00:00:00Z".
    *   `toDateTime` (optional, string ISO8601).
*   `limit` (optional, number): Max results (1-250).
*   `offset` (optional, number): Results offset for pagination.
*   `sort` (optional, string enum): e.g., "updateDate+asc", "updateDate+desc".

**`congress_getSubResource` Tool Parameters:**
*   `parentUri` (required, string): MCP URI of the parent entity (e.g., "congress-gov://bill/117/hr/3076").
*   `subResource` (required, string enum): Type of sub-resource (e.g., "actions", "cosponsors"). Valid values depend on the parent URI type.
*   `limit` (optional, number): Max results for list sub-resources.
*   `offset` (optional, number): Results offset.

*For the most accurate and detailed parameter information, including all enum values and specific constraints, refer to the tool descriptions provided by the server through MCP mechanisms or by inspecting the Zod schemas in `src/tools/*/searchParams.ts` and `src/tools/*/getSubResourceParams.ts`.*
